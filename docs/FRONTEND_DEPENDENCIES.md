# Frontend dependency security

The 15 November 2026 audit found 11 moderate reports in development tooling.
Two underlying advisories propagated through js-beautify, EditorConfig, Vue Test
Utils and typescript-eslint. `npm audit --omit=dev` reported zero vulnerabilities;
the vulnerable packages were not application runtime dependencies.

| Package | Previous resolved version | Reviewed resolution | Advisory |
| --- | --- | --- | --- |
| glob | 13.0.7 | 14.0.2 | [GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) |
| minimatch in three nested locations | 10.2.6 | Deduplicated to existing 11.0.8 | [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) |

The root `overrides` pins glob to 14.0.2 and minimatch to 11.0.8. These are
deliberate major changes to transitive tooling dependencies: their compatibility
was checked on the supported Node 24, rather than inferred from the old parent
ranges. All direct dependency versions remain pinned as before. In particular,
Vue Test Utils remains 2.5.1 and typescript-eslint remains 8.72.2. Every runtime
package entry in the lock file is unchanged. path-scurry, used by glob, moves from
2.0.2 to 3.0.0 as part of the development-only resolution.

The lock file was regenerated by npm and then verified using a clean `npm ci`.
Merely adding overrides left two stale minimatch 10 entries in an earlier
candidate, so those candidate files were rejected. The committed resolution
contains only glob 14.0.2 and minimatch 11.0.8, and `npm ls glob minimatch --all`
reports a valid tree. Do not regenerate or delete the user's lock file to apply
this fix: install the reviewed committed lock with `npm ci`.

Validation: TypeScript, ESLint, all 21 frontend tests and the production Vite build
passed. A separate CLI check exercised js-beautify file-glob expansion and
EditorConfig indentation through the changed transitive packages. Both full
`npm audit` and `npm audit --omit=dev` reported zero vulnerabilities at verification.
The existing frontend workflow now runs the full audit with a moderate threshold.
These checks make no model requests and do not change API/SQLite state.

Keep these overrides explicit until parent packages adopt compatible fixed
dependencies. On a future update, review the affected tree, regenerate the lock
with Node 24/npm, and run the same checks before removing or changing the pins.
