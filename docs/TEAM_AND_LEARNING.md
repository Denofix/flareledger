Both reviewed evidence and coordinated releases. These descriptions follow project changes and operator reports, rather than assigning work to absent participants.

| Skill practised | Concrete work | Learning outcome |
| --- | --- | --- |
| Product scope | Built an inspectable source-first workflow | A clear evidence boundary is more useful than an unsupported safety promise |
| Python/FastAPI/SQLite | Explicit import, API contracts and read-only corpus access | Import, readiness and state migration are different operations |
| Vue/TypeScript | Responsive browsing, charts, navigation and structured errors | Interface labels must match physical quantities and actual API states |
| Source provenance | DOI, versions, hashes, raw rows, locators and licenses | Metadata, downloaded files and measured results are different evidence |
| Scientific-data handling | Preserved units, blanks, over-range readings and camera limits | Unknown is not zero; equal units do not make quantities interchangeable |
| Bounded SI integration | Context selection, structured claims, citations, timeouts and quotas | Valid JSON and citation markers do not establish a supported conclusion |
| Evaluation/testing | Frozen questions, source anchors, mocked transport and separate receipts | Retrieval coverage, operational success and answer quality need separate evidence |
| Git collaboration | Branches, PR review, CI and squash merges | Shared integration needs a recorded revision and independent team review |
| Linux/deployment | Docker/Compose, Vercel-to-VPS routing, HTTPS and private runtime configuration | A build, readiness and a complete public workflow establish different things |
| Reliability | Persistent quota history, monitoring, snapshots and off-host copies | Backups need integrity and recovery checks |
| Responsive verification | Desktop, 360/390 px and tablet-width checks | Screenshots explain visible states but do not replace interaction tests |
| Technical communication | English documentation, public references and concise demo content | Submission must be accessible, readable and honest about unfinished work |

These are practical learning outcomes, not claims of scientific accreditation, independent experimental validation or NASA approval.
